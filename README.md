# 가맹저울 · 공정위 가맹사업 데이터 수집기 + 웹페이지

공정거래위원회 가맹사업 정보를 수집해 제안 1 디자인의 웹페이지(목록 → 진단 리포트 → 비교)로 보여주는 프로젝트입니다.
Python 3.9 이상만 있으면 되고, 추가로 설치할 패키지는 없습니다.

```
gamaeng-jeoul/
├─ run.py              실행 파일 (check / inspect / collect / build / serve)
├─ config.py           수집 연도·업종, 요청변수 이름, 응답 항목명 후보
├─ .env.example        인증키와 요청주소 (복사해서 .env 로)
├─ overrides.json      자동 추출이 틀린 값을 손으로 바로잡는 파일
├─ collector/          수집·해석·가공 코드
├─ data/               원본 저장소(raw.sqlite3), 검토 파일(review.csv)
└─ site/               웹페이지 (index.html + build 가 만드는 data.json)
```

## 데이터 흐름

| 단계 | 사용하는 API | 만들어지는 것 |
|---|---|---|
| 브랜드 목록 | 공정거래위원회_가맹정보_브랜드 목록 정보 제공 서비스 | 업종별 브랜드, 가맹본부 |
| 가맹점 현황 | 공정거래위원회_가맹정보_브랜드별 가맹점 현황 제공 서비스 | 가맹점 수, 평균매출, 폐점률·순증가율·명의변경률, 개점·폐점 흐름 |
| 업종 기준선 | 공정거래위원회_가맹정보 주요 업종별 가맹점수, 개폐점률 현황 제공 서비스 | 업종 평균 폐점률·개점률 |
| 정보공개서 목록 | 가맹사업정보제공시스템 정보공개서 공개본 목록 조회 (type=list) | 브랜드별 정보공개서 일련번호(jngIfrmpSn) |
| 정보공개서 본문 | 가맹사업정보제공시스템 정보공개서 본문 조회 (type=content) | 초기비용 항목, 직영점 수, 업력, 법 위반 이력 (자동 추출) |
| (선택) 지역 매출 | 공정거래위원회_가맹정보_지역별 업종별 평균 매출액 현황 제공 서비스 | 지역 기능용. 기본은 꺼져 있음 |

수집(`collect`)은 원본 응답을 그대로 `data/raw.sqlite3` 에 저장하고, 가공(`build`)은 저장된 원본만 읽습니다.
그래서 항목명이나 계산 규칙을 고쳐도 API 를 다시 부를 필요 없이 `build` 만 다시 하면 됩니다.

## 처음 한 번 하는 설정

### 1. .env 만들기

`.env.example` 을 `.env` 로 복사하고 채웁니다.

- `FTC_FRANCHISE_KEY` : 가맹사업정보제공시스템 마이페이지에서 발급받은 키
- `DATA_GO_KR_KEY` : 공공데이터포털 일반 인증키 (인코딩·디코딩 키 아무거나. 호출이 안 되면 다른 쪽으로 바꿔 보세요)
- `DGK_..._URL` : 공공데이터포털 마이페이지 → 활용신청 현황 → 각 API 상세 화면의 **상세기능 요청주소** 전체를 붙여넣습니다.
  (예: `https://apis.data.go.kr/.../get...` 형태. 서비스 URL 만 넣지 말고 상세기능 이름까지 포함해야 합니다.)

`.env` 에는 인증키가 들어 있으니 다른 사람에게 보내거나 깃에 올리지 마세요.

### 2. 설정 점검

```bash
python run.py check
```

### 3. 응답 항목명 맞추기 (가장 중요)

`config.py` 의 `FIELDS` 에 들어 있는 항목명은 실제 응답을 보기 전에 넣은 **추정값**입니다.
아래 명령은 API 를 5건만 호출해서 실제 항목명과 매칭 결과를 보여줍니다.

```bash
python run.py inspect brand_list --year 2024
python run.py inspect brand_stats --year 2024
python run.py inspect industry_stats --year 2024
python run.py inspect ftc_list --year 2024
```

각 결과 맨 아래 "config.FIELDS 매칭 결과" 에서 `없음` 으로 나온 항목은, 위에 출력된 실제 항목명 중 맞는 것을
`config.py` 의 해당 목록 맨 앞에 추가하세요. 함께 확인할 것:

- **요청변수 이름**: 연도 변수가 `yr` 이 아니면 `DATA_GO_KR[...]["year_param"]` 을 명세서대로 고칩니다. 필수 요청변수가 더 있으면 `extra` 에 넣습니다.
- **금액 단위**: 평균매출 단위를 명세서에서 확인해 `SALES_UNIT` 을 맞춥니다 (기본값 천원).
- **업종명**: `TARGET_SECTORS` 를 브랜드 목록의 실제 업종명과 똑같이 적습니다 (예: "커피" 인지 "카페" 인지).
- **JSON 지원 여부**: JSON 요청변수 이름이 다르면 `DGK_COMMON["format_param"]` 을 고칩니다. XML 로 와도 자동 해석합니다.

정보공개서 본문은 일련번호 하나로 먼저 확인해 보세요 (`ftc_list` 결과의 jngIfrmpSn 값).

```bash
python run.py inspect ftc_content --sn 151420
```

본문 앞부분과 함께 초기비용·직영점·설립연도·법 위반 추출 결과와 근거 문장이 나옵니다.

## 수집 → 가공 → 확인

```bash
python run.py collect        # 전체 수집 (처음엔 시간이 걸립니다)
python run.py build          # site/data.json 과 data/review.csv 생성
python run.py serve          # http://localhost:8000 에서 확인
```

- 특정 소스만 다시: `python run.py collect --only brand_stats,industry_stats`
- 정보공개서 본문 빼고: `python run.py collect --skip-content`
- 받은 본문까지 새로: `python run.py collect --only ftc_content --refresh`

### 호출 수와 트래픽

연도 5개 × 공공데이터포털 API 3개는 페이지 수만큼 호출되고, 정보공개서 본문은 브랜드당 1회입니다.
본문은 `TARGET_SECTORS` 업종에서 가맹점 수 상위 `CONTENT_LIMIT_PER_SECTOR` 개(기본 60)만 받습니다.
개발계정 일일 한도에 걸리면 다음 날 이어서 실행하면 되고, 이미 받은 본문은 건너뜁니다.

### review.csv 확인과 overrides.json

정보공개서 본문은 브랜드마다 표 형식이 달라 자동 추출이 틀릴 수 있습니다.
`data/review.csv` (엑셀에서 바로 열림) 에 추출값과 **근거 문장**이 있으니 확인하고,
틀린 값은 `overrides.json` 에 브랜드명으로 적은 뒤 `build` 를 다시 하세요.

```json
{
  "바삭치킨": {"parts": [1000, 300, 500, 4100, 1950], "direct": 12, "age": 18, "viol": 0}
}
```

금액은 만 원 단위, `parts` 순서는 [가맹금, 교육비, 보증금, 인테리어, 기타] 입니다.
확인되지 않은 값은 화면에 "정보 없음" 으로 나오고, 진단 점수에서는 중간값으로 처리됩니다.

## 계산 방식

- 폐점률 = (계약종료 + 계약해지) ÷ 전년도 가맹점 수 × 100
- 순증가율 = (올해 가맹점 수 − 전년도 가맹점 수) ÷ 전년도 가맹점 수 × 100
- 명의변경률 = 명의변경 ÷ 전년도 가맹점 수 × 100
- 진단 점수 = 수익성 30 + 비용효율 20 + 안정성 30 + 본부 신뢰도 20 (업종 내 상대평가)
- 회수기간 = 초기비용 ÷ (연매출 × 이익률 ÷ 12), 이익률은 화면에서 조정 (기본 8%)

업종 통계 API 의 개폐점률은 공정위가 정한 기준으로 계산된 값입니다. 명세서에서 분모와 폐점 범위를 확인하고,
위 브랜드 폐점률 계산식이 다르면 `collector/build.py` 의 `close` 계산을 같은 기준으로 맞추세요.

## 배포

`site/` 폴더(index.html + data.json)만 올리면 되는 정적 사이트입니다. GitHub Pages, Netlify, 일반 웹호스팅 어디든 됩니다.
인증키는 `site/` 에 들어가지 않습니다. 정보공개서는 연 1회 갱신되므로 1년에 한두 번 `collect` → `build` 후 data.json 만 바꿔 올리면 됩니다.

## 알아둘 점

- 공정위 활용가이드의 1번 샘플 주소에는 `/api/api/search.do` 처럼 `api` 가 두 번 들어가 있는데, 오타로 보입니다. 이 코드는 `/api/search.do` 를 사용합니다.
- 정보공개서 Viewer(`viewer.do`)는 주소에 인증키가 들어가야 해서 웹페이지에 직접 연결하지 않았습니다. 화면의 "정보공개서 원문 찾기"는 가맹사업거래 홈페이지로 연결됩니다.
- 공공누리 이용조건에 따라 출처 표시가 필요합니다. 웹페이지 하단에 자동으로 표시됩니다.
- data.json 이 없으면 웹페이지는 예시 데이터로 열리고, 화면 위에 그 사실을 알려줍니다.
